Architecture

The implementation is a strict one-way pipeline: every stage is a pure function over its input and a diagnostic reporter, and later stages consume annotations rather than re-deriving meaning.

2. Lexer and parser

The lexer scans UTF-8, decodes escapes and literal rune values, and implements automatic semicolon insertion: a newline terminates a statement after an identifier, literal, ), ], }, return, break, continue or ?, and is suppressed inside parentheses and brackets. Interpolated strings are split into literal and expression segments, where each expression segment carries its byte range and optional format spec.

The parser is a hand-written recursive descent parser with a Pratt-style expression parser. Two ambiguities are resolved without a separate grammar layer: noStructLit disables composite literals while parsing control-flow headers, and Name[...] is tentatively parsed as generic arguments and rolled back when it turns out to be an index. Interpolation placeholders are re-lexed with positions anchored in the original file, so diagnostics inside {...} point at the right column.

3. Semantic analysis

Checking runs in passes: named types are declared first, then fields and variants are filled, then imports are processed (so signatures may name imported types), and finally bodies are checked. The checker returns an annotation bundle keyed by node pointer:

AnnotationRecords
Typesthe checked type of every expression
Ranksthe region rank of every expression
Constsfolded compile-time constants
Identsthe resolved symbol for each identifier use
Calls, Fields, Variants, Patternscall, field, variant and pattern resolutions
FnSigs, MethodDefs, Defssignatures, method receivers and named type definitions

Region ranks are the safety mechanism that replaces lifetime annotations. The current region depth is tracked, and assigning or returning a heap value of a deeper rank than its destination is a compile error with a promote(...) suggestion. Owned values are tracked as affine: move positions are the right-hand sides of declarations and assignments, call arguments, returns and literal elements; method receivers are borrowed.

4. Bytecode and lowering

The compiler lowers the checked AST into fixed-width stack-machine instructions. Locals live in stack slots; calls push a frame; returns truncate to the frame base. Instructions carry source lines so runtime errors can report a call trace.

lowering highlights
locals      LOAD_LOCAL STORE_LOCAL MOVE_LOCAL DROP_LOCAL
aggregates  GET_FIELD SET_FIELD GET_INDEX GET_SLICE NEW_LIST
            NEW_STRUCT NEW_ENUM GET_TAG ENUM_FIELD
control     JUMP JUMP_IF_FALSE JUMP_IF_TRUE_KEEP JUMP_IF_FALSE_KEEP
calls       CALL RETURN BUILTIN
memory      ALLOC_NEW ALLOC_ARRAY PROMOTE REGION_ENTER REGION_EXIT
ownership   DROP ARENA_REWIND
  • ? stores its operand in a temp, tests the tag, and on failure emits ARENA_REWIND followed by construction of the function's None or Err and a return.
  • match evaluates the subject into a local and tests each arm by loading from that slot, so failed tests never leak operands on the stack.
  • comp emits a placeholder constant; after all functions compile, each site is wrapped in a synthetic function and executed in a sandboxed VM whose result patches the constant.

5. Virtual machine

Values are tagged: scalars inline, heap objects referenced. Frames record the function, instruction pointer, local base and an arena snapshot taken at entry (used by ? and destructors). The VM has a 100,000-frame call-depth limit, so runaway recursion fails with a clear error instead of exhausting memory. Builtins are dispatched from a single registry shared by the checker, compiler and VM.

6. Arena runtime

The arena is a list of slabs with a bump pointer. Allocation returns slots with capacity to the end of the current slab, which is what allows a list at the bump head to grow in place.

arena state
slabs [][]Value     committed slabs
slabIdx, head      bump pointer
marks []mark       region stack (slab, head) snapshots
gens []uint64      generation per depth

enter()   push a mark, bump the depth generation
exit()    restore the mark, advance the generation
valid(v)  reject values whose (depth, generation) is stale
atHead()  grow a list in place by advancing the pointer
trim()    drop trailing slabs and tail capacity (mem.Trim)

Exiting a region is a pointer restore: cost does not depend on the number of objects allocated. Promotion deep-copies into the parent region; strings are immutable and shared. In the interpreter, physical reclamation is delegated to Go's collector, while the semantics and costs of the model are enforced by the VM and checker. The planning AOT runtime replaces the slab list with real page decommits.

8. Where the future plugs in

  • AOT compiler consumes the same bytecode program, lowers it through a region-aware IR and emits C, Wasm or JavaScript.
  • Fibers are additive: the scheduler interface exists, and per-fiber arenas use the same arena type.
  • Deterministic simulation testing requires three seams: capability-gated clocks and randomness, a swappable scheduler hook, and a yield check at every synchronization point.
  • Capability security computes an effective mask per external module and rejects denied uses during checking; comp.HasCap folds into compile-time evaluation.
  • Attribute macros will add an expansion pass between name resolution and type checking, with user-defined compile-time functions rewriting the tree.
The rationale for each decision is in the architecture decision records.
