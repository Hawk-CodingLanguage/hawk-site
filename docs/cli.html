CLI reference

The toolchain is a single binary, hawk. Program output goes to stdout, toolchain messages go to stderr, and exit codes are meaningful for scripts.

Commands

CommandBehavior
hawk run <file.hawk> [-- args...] Compile and interpret. Arguments after -- appear in os.args(), with the script path as element zero. The exit code is the program's.
hawk check <file.hawk> Run the full frontend without executing. Silent on success; diagnostics to stderr and exit 1 on errors.
hawk diff [--semantic] [--json] <old> <new> Semantic AST diff. Exit 0 when there are no semantic changes, 1 when there are, 2 on usage or parse errors.
hawk patch apply [--check] [--dry-run] <patch.hawkpatch> [target] Apply a structural patch. Validates and type-checks the result before writing; writes go through a temp file and rename.
hawk build <file.hawk> [-o out] Type-checks, then reports that AOT compilation is planned and exits 2.
hawk pkg <command> Reports that package management is planned and exits 2.
hawk merge <base> <ours> <theirs> Structural three-way merge is planned; currently exits 2 with a pointer to the ADR.
hawk version, hawk help Version string and usage.

Exit codes

CodeMeaning
0Success, or no semantic changes for diff
1User or program error: diagnostics, runtime failure, or differences found by diff
2Usage error, or a not-yet-implemented command
program-definedhawk run returns the value passed to os.exit(code)

Running programs

terminal
$ hawk run examples/tour.hawk
sum 1..10 = 55
fib(10) = 55
...

$ hawk run tool.hawk -- input.txt --verbose
$ echo $?
0

$ hawk run failing.hawk
hawk: runtime error: integer division by zero
  in helper at line 2
  called from main (line 5)

Semantic diff

diff parses both files and compares structure. Formatting changes, comment edits and reordered imports produce no output; structural changes are reported by intent.

terminal
$ hawk diff --semantic old.hawk new.hawk
+ struct Metrics added
~ struct Server (modified):
  ~ field 'port': type changed from 'u16' to 'u32'
~ fn start (modified):
  ~ body modified

$ hawk diff --json old.hawk new.hawk
{
  "old_file": "old.hawk",
  "new_file": "new.hawk",
  "changes": [
    { "op": "change_field_type", "owner_kind": "struct", "owner": "Server",
      "member": "port", "from": "u16", "to": "u32" },
    { "op": "add_decl", "owner": "Metrics", "note": "struct" },
    { "op": "change_body", "owner_kind": "fn", "owner": "start" }
  ]
}

Structural patches

A .hawkpatch document is JSON with a target, an optional base hash and a list of typed mutations. Supported operations include add_field, remove_field, rename_field, set_field_type, add_variant, remove_variant, rename_symbol, add_import, remove_import and insert_arm.

fix.hawkpatch
{
  "target": "src/models.hawk",
  "base_hash": "sha256:...",
  "mutations": [
    { "op": "rename_symbol", "scope": "global",
      "old_name": "validate_session", "new_name": "check_session" },
    { "op": "insert_arm", "function": "classify",
      "match_index": 0, "arm": "1 => \"one\"" }
  ]
}
terminal
$ hawk patch apply --check fix.hawkpatch    # validate, write nothing
$ hawk patch apply --dry-run fix.hawkpatch  # print the patched source
$ hawk patch apply fix.hawkpatch            # validate, then write atomically
A rejected patch never touches disk. The patched source is re-parsed and type-checked first; if it does not compile, the command exits 1 and leaves the file byte-for-byte unchanged.

Planned commands

  • hawk pkg gains get, sync, upgrade, vendor and audit with BLAKE3 lockfiles and capability clamps.
  • hawk merge becomes a structural three-way merge and a git merge driver.
