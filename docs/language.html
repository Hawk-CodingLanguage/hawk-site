1. Program structure and imports

A program is one file of declarations. Execution starts at fn main(), which takes no parameters and returns no value. Declarations are use, const, struct, enum, impl and fn.

structure.hawk
use std.fmt.{ Println, Format }
use std.core.{ Option, Result }

const LIMIT: i64 = 10

struct P { x: i64 }

impl P {
    fn get(self) -> i64 { return self.x }
}

fn main() {
    Println("hello")
}

use is the only import keyword and there are no wildcards. Standard library modules resolve by canonical path (std.fmt, std.mem, std.collections, std.core, std.fs) or by their unique last segment, so math.sqrt(4.0) works without an import. The namespace root and nested modules can be imported too: use std enables std.fmt.println(...), and use std.{ fmt, mem } binds the submodules. Grouped imports may alias members: use std.collections.{ List, Span as View }. Type members and enum variants can be imported as well: use Shape.{ Circle, Rect }.

Wildcards are rejected: wildcard imports are not supported; import names explicitly (no wildcard pollution). URL imports required the package manager and currently report that they are planned.

2. Lexical structure and literals

  • Comments: // line and /* block */.
  • Statements end at newlines (Go-style automatic semicolon insertion) and are ignored inside (...) and [...], so an opening brace or literal must stay on the same line as the construct that precedes it.
  • Integers: decimal, 0x hex, 0b binary, 0o octal, with _ separators. Floats support exponents and underscores.
  • Strings: "..." with escapes, backtick raw strings (never interpolated), and rune literals such as 'a' that produce integer code points.

Double-quoted strings interpolate {expr} and {expr:spec}; literal braces are written {{ and }} or escaped with \{ and \}. Raw strings do not interpolate.

interpolation.hawk
fn main() {
    name := "Ada"
    latency := 1.4285
    port := 8080

    println("server {name} on port {port}")
    println("latency {latency:.2} ms")
    println("port 0x{port:04X}, next {port + 1}")
    println("literal braces {{like this}}")
}

Specs use the grammar [0][width][.precision][verb] with verbs d, x, X, b, o, f, e, E and s. A leading 0 zero-pads; otherwise the value is right-aligned to the width.

There are no implicit numeric conversions except literal adoption: x: u8 = 5 is fine, but assigning an i64 variable to a u8 requires value as u8. Casts truncate and wrap like C.

4. Bindings and assignment

bindings.hawk
name := "Alice"        // immutable, inferred as str
port: u16 = 8080       // immutable, explicit type
mut total := 0         // mutable
total += 1             // compound assignment

file := File.open("out.txt")
file.write("data")
file.close()

Assignment targets are variables, struct fields and container elements. Compound assignment exists for every arithmetic and bitwise operator. Owned values are affine: assigning, passing or returning them moves ownership, and using a moved value is a compile error. Method receivers are borrowed, so calling file.write(...) does not consume the handle.

5. Control flow and pattern matching

control.hawk
if cond { ... } else if other { ... } else { ... }

while cond { ... }

for i := 0; i < n; i += 1 { ... }
for x in collection { ... }        // List, Span, str, Map keys
for { ... }                        // infinite

label := match status {
    200..299 => "OK",
    400 => "Bad Request",
    404 => "Not Found",
    500..599 => "Internal Error",
    _ => "Unknown"
}

Pattern forms:

FormExampleNotes
wildcard_matches anything, binds nothing
bindingnmatches anything, binds it
literal0, -1, "ok", true
enum variantSome(x), Color.Red, Rect(w, h)payload patterns nest
structPoint { x, y: 0 }shorthand binds the field; all fields with irrefutable subpatterns is exhaustive
range200..299, 0x20..0x7Einclusive; bounds must be compile-time constants
or0x00 | 0xFF, A(n) | B(n)alternatives must bind the same names with the same types

Arms may add a guard: Key(KeyEvent { key, pressed: true }) if key < 10 => .... Guarded arms never satisfy exhaustiveness, so a fallback arm is required. Enum matches must cover every variant unless a wildcard or binding arm is present.

6. Memory: regions, ownership, views

Scoped arenas

regions.hawk
region {
    scratch := alloc.NewArray[i64](128)      // zero-initialized
    scratch[0] = 1
    cell := alloc.New[i64](7)
    println(promote(scratch))                // copy outward
}                                            // reclaimed in O(1)

released := mem.Trim()
  • Allocation inside a region is a pointer bump; leaving the region restores the arena in a single instruction.
  • alloc.New[T](v) allocates an initialized cell; alloc.NewArray[T](n) allocates zeroed elements.
  • promote(x) copies a value into the enclosing region and is required for anything that escapes; escaping without it is a compile error with a promote suggestion.
  • Lists sitting at the bump head grow in place without copying; mem.Trim() releases unused committed capacity.

Resource cleanup

Resources such as File are ordinary values with no automatic destructor invocation: release them explicitly with close(). Space allocated inside a region is reclaimed when the region exits, and ? rewinds the arena to the function-entry mark on failure so abandoned allocations from failed steps do not accumulate.

Zero-copy views

Slicing a str shares its bytes. list.span() and list[a:b] produce a Span[T] that indexes, iterates and assigns through to the backing list. A span cannot outlive its container, which the region rank rules enforce.

7. Errors as values

Hawk has no null and no exceptions. Absence and failure are built-in enums imported from std.core; tags are fixed at None = 0, Some = 1, Ok = 0, Err = 1.

errors.hawk
fn parse_double(s: str) -> Result[i64, str] {
    n := s.parse_i64()?         // Err(e) returns Err(e)
    return Ok(n * 2)
}

fn first_even(xs: List[i64]) -> Option[i64] {
    for x in xs {
        if x % 2 == 0 { return Some(x) }
    }
    return None
}

The postfix ? unwraps the success case and propagates failure to the enclosing function, whose return type must match: a Result function propagates Err with the identical error type, and an Option function propagates None. On the failure branch the compiler rewinds the arena to its position at function entry, so temporaries allocated by a failed step are reclaimed in O(1).

TypeMethods
Option[T]is_some, is_none, unwrap, unwrap_or, ok_or(err)
Result[T, E]is_ok, is_err, unwrap, unwrap_err, unwrap_or, ok()

Capitalized aliases (IsSome, Unwrap, OkOr, and so on) are available for each method. unwrap on None or Err is a runtime error with a source location and a call trace.

8. Compile-time evaluation

comp runs ordinary Hawk code during compilation using the same checker, compiler and virtual machine as the runtime.

compiletime.hawk
const BufferSize: i64 = comp(1024 * 1024)
const Greeting: str   = comp("hawk" + "!")

fn fib(n: i64) -> i64 {
    if n < 2 { return n }
    return fib(n - 1) + fib(n - 2)
}

const FIB20: i64 = comp { return fib(20) }

const TABLE_SUM: i64 = comp {
    mut total := 0
    for i := 0; i < 10; i += 1 { total += i * i }
    return total
}

comp.Assert(BufferSize == 1048576, "buffer size must be 1 MiB")
  • comp(expr) infers its type from context; comp { ... } must return a value and needs a scalar type context.
  • Results are scalars and str today; composite results are staged for the AOT milestone.
  • Evaluation is sandboxed: no os.* or File.*, output is discarded, execution is capped at 10^7 VM instructions and 100,000 call frames, and each evaluation uses an isolated arena. Results are deterministic.
  • comp.Assert(cond, msg) fails the build with compile-time assertion failed: <msg>.

10. Diagnostics

Toolchain messages go to stderr with a source span and a caret; suggestions such as use promote(...) appear as notes. Runtime errors report the function, line and a call trace:

runtime error
hawk: runtime error: integer division by zero
  in helper at line 2
  called from main (line 5)

hawk check prints every diagnostic and exits 1 on any error.

11. Known limitations

  • User-defined generics and closures are parsed but rejected with a pointer to the roadmap; built-in generics infer normally.
  • Owned fields and recursive drops are staged; containers do not yet recurse into resources held in containers.
  • Non-lexical lifetimes are scope-based: drops happen at scope end, before return, and on loop exits, but not at last use.
  • Value semantics for structs is an AOT decision; the interpreter uses reference semantics for aggregates.
  • AOT compilation, fibers, packages and capability security are scaffolded and documented in the ADRs.
  • Time and randomness are deliberately absent from the core so that deterministic simulation testing remains possible.
