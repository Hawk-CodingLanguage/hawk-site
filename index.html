Hawk is a statically typed systems and scripting language that pairs Go's structural simplicity with Rust's performance goals and C's hardware transparency — through scoped bump arenas and deterministic ownership instead of a tracing collector or a borrow checker.

errors.hawk
use std.fmt.{ println }
use std.core.{ Option, Result }

fn parse_port(text: str) -> Result[u16, str] {
    n := text.parse_i64()?
    if n < 1 || n > 65535 {
        return Err("port out of range: {n}")
    }
    return Ok(n as u16)
}

fn main() {
    match parse_port("8080") {
        Ok(port) => println("listening on port {port}"),
        Err(e)   => println("config error: {e}")
    }
}
Design pillars

Four ideas carry the whole language

Everything else in Hawk follows from these decisions, and each one is enforced by the compiler rather than by convention.

region

Scoped bump arenas

Allocation is a pointer bump. Leaving a region reclaims everything in O(1) with no per-object frees and no fragmentation. Lists at the bump head grow in place, and mem.trim() releases unused pages.

mut

Explicit mutability

Bindings are immutable by default — x := 1, name: T = value — and mut opts into reassignment. There is no ownership keyword, no lifetime annotation and no borrow checker.

Option · Result · ?

Errors as values

No null pointers and no exceptions. Absence and failure are ordinary enums, and the postfix ? operator propagates them while rewinding the arena so failed steps leave no garbage.

comp

Compile-time evaluation

comp(expr) and comp { ... } run normal Hawk code in a sandboxed, step-limited VM and bake the result into the binary. comp.assert(...) fails the build on bad assumptions.

Language

Readable like Go, strict where it matters

Automatic semicolons, immutable bindings with := and mut for reassignment, methods on structs, exhaustive match, string interpolation, and built-in generic collections — with no lifetime annotations anywhere.

patterns.hawk
use std.fmt.{ println }

enum Event {
    Key(KeyEvent),
    Quit
}

struct KeyEvent {
    key: i64,
    pressed: bool
}

fn describe(e: Event) -> str {
    return match e {
        Key(k) if k.key < 0 => "invalid",
        Key(KeyEvent { key, pressed: true })
            if key < 10 => "modifier {key}",
        Key(KeyEvent { key, pressed: true }) => "key {key}",
        Key(KeyEvent { pressed: false }) => "released",
        Quit => "quit"
    }
}

fn main() {
    println(describe(Event.Key(KeyEvent { key: 3, pressed: true })))
}
  • Exhaustive pattern matching. Enum subjects must cover every variant; guarded arms never count toward exhaustiveness.
  • Struct patterns and nesting. Destructuring reads fields directly — no copies, no allocations, no lifetime churn.
  • Ranges and or-patterns. 200..299, 0x00 | 0xFF and A(n) | B(n) with shared bindings.
  • String interpolation. "port {port} latency {latency:.2}" captures variables, expressions and format specs directly.
  • Explicit imports, no wildcards. use std.fmt.{ println, format } — collisions are impossible by construction.
Memory model

Arenas you can see, lifetimes you never write

Hawk replaces both manual memory management and tracing collection with a single mechanism: lexically scoped arenas for bulk data, with explicit mut bindings and explicit close() or defer for resources that need exact release moments.

region entry
scratch growth
region exit
outer scope region allocations reclaimed in O(1)

Exiting a region restores the bump pointer in a single instruction, regardless of how many objects were allocated. The compiler's lexical rank rules reject any value that would escape its region, and promote(x) makes an intentional copy outward explicit.

Nothing to collect

No stop-the-world pauses: regions are reclaimed deterministically when they exit, and failure paths rewind the bump pointer so abandoned allocations do not accumulate.

Nothing to annotate

There are no lifetime parameters. Region ranks are lexical, so region { ... } nesting is the entire mental model, and escape errors suggest promote(...).

Nothing to corrupt

Arena values are generation-stamped: any stale access is caught as use of value from an expired region rather than reading freed memory, even in the interpreter.

Tooling

One binary, structural from day one

Hawk's toolchain treats code as syntax trees, not text. Diffs and patches operate on structure, so reformatting and import reordering never show up as changes.

Status

Where the implementation stands

Hawk ships in milestones. The interpreter is complete and tested; the compiler, runtime and ecosystem are staged and documented in architecture decision records.

  • Done Interpreter — lexer, parser, type checker, bytecode VM, arenas, ownership, standard library, CLI, semantic diff and patch.
  • Done Compile-time evaluation — comp expressions and blocks, comp.assert, sandboxed execution quotas.
  • Next User generics and closures — monomorphized generic functions, types, and callable function values.
  • Next Tuples and generics — tuple types with destructuring, then user-defined generic functions and types.
  • Planned AOT compiler — region-aware IR with C, Wasm and JavaScript backends producing static binaries.
  • Planned Fibers and kernel I/O — M:N scheduler over io_uring, epoll, kqueue and IOCP; deterministic simulation testing.
  • Planned Package ecosystem — Git and URL dependencies, BLAKE3 lockfiles, vendoring, capability security.
